# Kubernetes ImagePullBackOff — ErrImagePull or registry denial

Runbook ID: RB-K8S-002
Category: kubernetes
Signals: ImagePullBackOff | ErrImagePull | pull access denied
Summary: The node cannot fetch the referenced image because the digest/tag, registry credentials, network path or platform is invalid.
Sandbox commands: kubectl describe pod sentinel-demo | sentinel-sim restore-known-image-digest

## Scope and safety
Kubernetes image distribution. Container application logs may not exist because the image never started.

These are synthetic training incidents, not records of a real outage. All commands in SentinelOps execute only as sandbox receipts. Confirm impact, affected scope and change ownership before a real operator takes action.

## Symptoms and error evidence
The synthetic rollout referenced a tag absent from the production registry. Pod events showed manifest unknown followed by ImagePullBackOff.

Preserve timestamps and sanitized request/event IDs. Treat one symptom as evidence to investigate, not proof of a single cause.

## Diagnostic procedure
1. Inspect kubectl describe pod sentinel-demo events for manifest unknown, unauthorized, TLS or timeout errors.
2. Verify the image repository, immutable digest, architecture support and registry availability.
3. Check imagePullSecrets reference and service account in the correct namespace without printing registry tokens.

## Root cause hypothesis
The node cannot fetch the referenced image because the digest/tag, registry credentials, network path or platform is invalid. Correlate this hypothesis with the diagnostic results and the most recent authorized change. If the evidence contradicts it, stop and retrieve additional context rather than executing the proposed plan.

## Remediation and approval
Fixed simulation plan: `kubectl describe pod sentinel-demo` followed by `sentinel-sim restore-known-image-digest`. The second action is mutating and requires human approval. These commands are recorded as simulation receipts, never executed by a shell.

1. Request approval to restore a known available image digest via the fixed sandbox action.
2. For real credential repair, rotate the approved pull secret through secret management and least-privilege registry access.
3. Do not switch to an untrusted image or disable registry TLS verification.

## Validation and rollback
Success criteria: Nodes pull the intended digest and the workload becomes ready with a stable restart count.

Rollback: Restore the last verified digest and secret reference; keep provenance and vulnerability policy checks enabled.

Record before/after evidence and the change approver. Recovery must be verified by real monitoring; a successful simulation is not production recovery.

## Synthetic post-mortem and prevention
The pipeline promoted manifests before image replication completed. Add registry availability and digest-verification gates.

The incident owner should document the detection gap, contributing change, remediation evidence and follow-up owner. An incomplete RCA should remain a hypothesis until independently validated.
